# SECURITY — Order Book Mind Reader

No user data, no accounts, no keys. The risks are **look-ahead leakage**,
**provider terms**, and **misleading claims**.

## 1. Secrets

| Secret | Needed | Notes |
|---|---|---|
| exchange keys | **no** | this project never places an order |
| model API keys | no | the transformer is trained locally |
| anything | no | if a tutorial asks for a key here, it is the wrong tutorial |

`.gitignore` covers `.env*` with `!.env.example` (there is no `.env` in use).

## 2. Leakage controls (the real security surface)

| Control | Prevents | Where |
|---|---|---|
| purge + embargo = context + label horizon | windows straddling the split | `train.embargo_for` |
| fold-local normalisation | test statistics in training | `features.Normalizer` |
| `features.py` cannot import `labels.py` | accidental target use in inputs | module direction |
| lag tests | `shift(-1)` creeping in | `tests/test_labels.py` |
| paired prediction intersection | comparing models on different rows | `run_model.py` |
| archive end date stated | implying recent performance | `docs/TRD.md`, README |

A model that "wins" by 0.02 nats should be assumed leaky until the lag test and
the fold boundaries have been checked. That assumption is cheaper than a retraction.

## 3. Provider terms and load

| Host | Constraint |
|---|---|
| `data.binance.vision` | public bulk data; one sequential request per file; verify `.CHECKSUM` |
| Hyperliquid (fallback) | public WS; rate limits documented in project 3 — do not hammer |

- Do not scrape the website; use the published buckets.
- Do not redistribute the archives in the repo. `data/` is gitignored.
- Attribute the source in the README and in any figure caption that shows data.

## 4. Model and artefact hygiene

- No pickle or `.pt` file is committed: a torch checkpoint is code execution.
  Checkpoints go to `outputs/` (gitignored) and are regenerated by `make model`.
- `torch.load` is never called on an untrusted file. If a checkpoint must be
  shared, share the config plus the seed, not the weights.
- No dependency is pinned to a git URL.

## 5. Claim integrity

| Slip | Why it matters | Detection |
|---|---|---|
| Reporting AUC without the bp edge | hides that the edge is below costs | `evaluate.verdict` is mandatory |
| Describing a probe as "the model uses X" | probes show decodability, not use | patching recovery is stated alongside |
| Quoting the article's 82% as a target | provenance unknown | not cited as a benchmark anywhere |
| Presenting 2023-24 results as current | the archive is frozen | stated in the first screen of the README |

## 6. Pre-publication checklist

- [ ] Bar verdict in the README matches `outputs/model_vs_baseline.csv`.
- [ ] The bp number and the cost line appear next to it.
- [ ] Every interpretability claim names its control result.
- [ ] Archive end date is in the README, not only in `/docs`.
- [ ] No `data/` or `outputs/` content in git.
